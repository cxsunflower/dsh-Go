# 像素奶蛙：动画与宠物包说明

像素奶蛙（Pixel Naiwa，`naiwa`）是供 DSH Go 导入的无声像素宠物包。经典黄色身体、奶油色肚皮、浅绿眼圈和灰褐色小爪绘制在 64×64 透明画布上，共 **24 段动画、861 帧**。全部帧见 [总览大图](../assets/naiwa-frames.png)，调色板、每段帧数和绘制方法见 [素材说明](../../app/tool/pet_src/naiwa/README.md)。

## 1. 播放规则

以 main 的 schema 1 解析器、状态归约和手势入口为准。App 保留原有内置宠物，奶蛙通过「设置 → 宠物 → 导入」安装；不需要奶蛙专属 App 接口。

动画中的代码字符已绘制在 PNG 帧里，不读取或吞掉聊天内容。拖动、游走和镜像遵循通用宠物规则；正视素材使用 `roam.faces: front`，不启用页面自由拖动。声音资源仅保留参考，动作不等待录音。

## 2. 场景与动画分配

| 入口 | 动画 | 触发与结束 |
|---|---|---|
| `idle` | `idle` | 范围内没有运行中的任务，呼吸、眨眼循环 |
| 待机池 | `idle-look`、`idle-giggle`、`snack`、`dance` | 四项等权；分别播放 2、2、1、2 遍，然后回待机 |
| `thinking` | `thinking` | 等模型、推理或重试期间 |
| `working` | `typing`、`typing-both`、`typing-fast` | 工具运行或流式回复；按全局运行会话数分成 1、2、3+ 档 |
| `juggling` | `terminal`、`terminals` | 子代理运行，按 1、2+ 档 |
| `attention` | `celebrate` | 一轮完成后 1.5 秒内没有新一轮；每次播放一次轻跃、“啦”口型与 ✅，共 2080 ms，然后返回当前状态 |
| `carrying` | `carrying` | 导入宠物包期间抱箱小步搬运，1320 ms 一轮；成功或失败后清除信号 |
| `error` | `shocked` | 一轮失败，默认显示 2180 ms |
| `notification` | `alert` | 有待确认、待回答事项，持续到处理完成 |
| `sweeping` | `eat-paper` | 上下文压缩期间 |
| `sleeping` / `waking` | `sleep` / `wake` | 无任务且 60 秒无交互后睡眠；触摸或任务唤醒，`wake` 播 1720 ms |
| `roam.anim` | `walk` | 聊天页待机时由 App 安排游走 |
| `tapLeft` / `tapRight` | `poke-left` / `poke-right` | 点身体左右半边，播放 900 ms |
| `tickle` | `laugh-roll` | 1.1 秒内三连点，依次捧腹大笑、打滚、起身回待机，播放 2940 ms |
| `annoyed` | `annoyed` | 同一窗口内继续到第六下，打断当前反应；鼓腮叉腰、跺脚后放松，播放 1530 ms 并清空点击计数 |
| `drag` | `crawl` | 拖动时交替伸爪、蹬腿趴行，配合轻微起伏和眨眼；松手后由 App 返回当前状态 |

导入使用独立的 `carrying`，六连点使用独立的 `annoyed`；`terminal` 对应子代理，`shocked` 对应出错。所有 24 段都有状态、档位、待机或交互入口，覆盖 main 的 11 个状态、游走及 5 类反应。

待机间隔是 `min: 10000`、`mean: 18000`、`max: 25000` 毫秒，每段插播结束后重新等待。待机小动作不延长 60 秒休眠计时；正在工作、拖动、隐藏或播放反应时不会强行插播。四种动作各有 25% 的抽取概率，不保证一轮清醒时间里全部出现。

三连点后的第 4、5 下按 main 规则重新播放 `laugh-roll`，第 6 下转为 `annoyed`。睡着时先唤醒；有待处理事项时，点按按 App 的跳转规则执行。反应到时返回当前状态，不延长为完整录音时长。

App 外悬浮窗支持状态、左右点按及拖动，但不游走、不触发三连点和六连点。`reactions` 使用基础名与字符串动画名，`tickle` 是主线接口名，对应素材为 `laugh-roll`；六连点和导入状态行为以当前 main 为准。

## 3. 美术约束

全部 24 段按各自动作节奏连续绘制。工作与子代理每段 2000 ms，上下文压缩 2400 ms，均为 50 ms 一帧。循环段补足末帧到首帧的身体、手脚和道具路径；单次反应收回待机。手臂按关节角度插值后以固定臂长重画，脚步与代码道具沿轨迹移动，保持像素轮廓清晰。出错保留惊跳和汗滴，不使用整身闪色或残影。

过渡帧里每个部件都按整像素、在同一帧一起移动：整体位移、脚掌、肚皮起伏和趴行小腿先取整再绘制，脚掌保持站立时的形状；手臂只在手掌跨到下一个像素时重画，躯干在所有姿势下保持宽度。头、胯、脚因此不会分几帧先后越过取整点，播放时没有沿身体爬行的波浪像素。

描边统一收成 1 像素线：肢体的描边与躯干、头或箱子的描边并排时，肢体向相邻描边补 1 像素，不叠成双线；描边围出的 1 像素小孔和窄缝直接连成线，轮廓上顶出的单个像素削掉。躯干、头和箱子保持原形，箱子只用自带的边框，不另加外描边。肚皮暗部不留孤立的单像素。

- `idle` 为 42 帧、2540 ms，每轮一次自然呼吸：吸气时胸腹、肚皮和双臂在同一帧整体上移 1 像素，双臂保持形状，脚底固定在 y = 60。躯干宽度不随呼吸变化，避免在左右手臂最外沿顶出孤立像素。头部轮廓固定，只按整像素平移，不参与呼吸或倾斜时的缩放、斜切；翻滚时随身体整体旋转。胸腹连接处与头部等宽，五官跟随头部并保持间距。所有未旋转的正面动作，头部平移对齐后逐像素核对轮廓。`idle-giggle` 的肩膀抖动同样保持双脚落地。
- 工作三档为单爪敲键盘、双爪交替敲键、快速打字，各 40 帧、2000 ms；资源名按画面取为 `typing`、`typing-both`、`typing-fast`。键盘挡在肚前、双臂之后，略带俯视：后沿较窄，浅色键面上是错开的两排键和空格键，深色前沿表现厚度，双脚露在下方。爪子真正落在键上：每次击键在键上停 1–2 帧，抬起 2 像素移到下一个键再落下；爪子轮廓正下方的那个键第一帧闪白并在下方透出蓝光，第二帧转蓝。每次击键在头顶上方放出一个代码字符向上飘。爪子只落在肩膀正下方或内侧的键上，手肘不向外张开。
  - `typing`：右爪按「哒哒、哒、哒哒、哒」的节奏敲，左爪扶着键盘后角，字符 1 像素一帧上浮。
  - `typing-both`：两爪各 400 ms 敲一下、相差半拍交替，左右各一列字符。
  - `typing-fast`：两爪各 200 ms 敲一下交替，字符 2 像素一帧快速上浮、停留 350 ms，分四列；每隔一次击键身体下沉 1 像素。
- 子代理用 `terminal` / `terminals` 表示指挥一个 / 两个终端小图标，各 40 帧、2000 ms。图标带 `>_` 提示符和动态光标，多个时左右轮流调度，不遮挡眼睛和嘴。
- `eat-paper` 为 48 帧、2400 ms 的吃长纸循环：长纸始终连着嘴，双爪交替送纸并持续吞咽；纸张长度保持不变，下端向前卷起，用白色高光、灰色背面和右侧卷口表现弧度；纸张下端连同卷口整段左右各摆 1 像素。条纹每帧向上移动 1 像素，每轮移动 48 像素，与 6 行重复印刷图案对齐。循环衔接无送入或收口停顿。纸张始终计入手持道具，进入嘴部时允许有意遮挡嘴型。
- `carrying` 为 26 帧、1320 ms 的抱箱循环：双爪握住箱边、左右脚交替迈步，身体与箱子同步轻晃。箱子绘在双臂后，不遮挡五官，不抛接代码。
- `annoyed` 为 31 帧、1530 ms 的单次反应：皱眉鼓腮、叉腰，左右脚各跺一下，最后闭眼放松、垂爪回到待机。嘴型闭合，不使用出错惊跳的汗滴、残影或换色。
- `celebrate` 为 34 帧、2080 ms 的单次完成动作：直接张口做“啦”的口型，双爪张开轻跃，绿色 ✅ 在头顶出现。开口参考进食嘴型的深度，“啦”10×8，张嘴与收口经过笑嘴和半张口过渡；“啦”的上排牙齿和宽舌头清晰可见。按 60 ms 连续补足抬臂、起跳、落地和收手，最后两帧各 80 ms，回到待机姿势。对勾与身体至少隔 1 个透明像素，独立于身体命中框。
- `laugh-roll` 为 49 帧、2940 ms 的单次反应，每帧 60 ms：前 24 帧连续捧腹起伏三次，共 1440 ms，保留加倍后的时长；随后 3 帧屈身、15 帧翻滚蹬腿和 7 帧起身，共 1500 ms。双脚沿弧线抬起，身体保持接地，最后回到待机。
- `crawl` 为 34 帧、1720 ms 的纯趴行循环，没有代码道具、张嘴或咀嚼。后脚为较薄的圆头椭圆，后腿与臀部之间恢复原来的分层描边接缝。前爪使用固定形状，手肘随爪落点弯曲。透明像素为 `(0,0,0,0)`，其它 alpha 为 255。
- 正视待机是比例基准：上臂约 4.61 像素、前臂 4 像素、爪半径 1.75 像素；趴爬沿用相同比例。手臂跟随肩膀，不被胸腹的缩放拉扯；绘制时肩肘统一到半像素关节坐标，前臂连接手掌的整数落点，减少手掌静止时的轮廓碎点变化。前臂填色在腕线收住，手掌末端保持灰褐色和描边，不露出黄色尖点。
- 脚底线 y = 60，身体中轴 x = 32；命中区只量身体，离体字符、气泡和音符不计入。
- 睁眼高光、眼睛与嘴型逐帧检查；捂嘴、吞长纸或字符和睡眠泡泡可有意遮挡嘴部。
- 直立进食的嘴中心为 (32,39)，只用于绘图一致性检查，不输出聊天粒子接口。
- `celebrate`、`wake`、`poke-left`、`poke-right`、`laugh-roll`、`annoyed` 不循环并回到待机姿势。其它动画循环播放，实际播放时长由状态或反应入口控制。

## 4. 来源、生成与打包

`app/tool/pet_src/naiwa/draw.py` 是画面和映射的输入，生成 `pet.json` 与 `sheets/*.png`。素材工具允许每段 4–64 帧、每帧 40–400 ms、全包不超过 1024 帧。`app/tool/make_pet_pack.py` 裁切、去重、量命中框，生成 `app/assets/pets/naiwa/pack.json` 与 24 张 PNG；不要手改这些生成物。

源格式的 `states`、`tiers`、`bonus`、`reactions` 引用既有动画。`bonus` 为空；`holds.attention: 1` 使完成动作只播放一遍。`holds` 将状态保持遍数换算成毫秒；`idlePool[].loops` 换算成插播时长。源格式的 `states.roam` 用来生成 `roam.anim`，App 的游走只读后者。反应值均为字符串，构建器检查动画引用有效。

生成的清单保持 `schema: 1`，不包含 `sounds`、`snack`、`roam.free` 或 `drag.mirror`。使用如下命令：

```bash
python app/tool/pet_src/naiwa/draw.py
python app/tool/pet_src/naiwa/draw.py --check --preview docs/assets/naiwa-frames.png
python app/tool/pet_src/naiwa/draw.py --check --strip crawl --gif crawl
python app/tool/pet_src/naiwa/draw.py --check --strip celebrate carrying annoyed laugh-roll --gif celebrate carrying annoyed laugh-roll
python app/tool/make_pet_pack.py --only naiwa
python tooling/pets/build_pet_pack.py --src app/assets/pets/naiwa --out app/build/pet_main_compat/pixel-naiwa.zip
```

ZIP 只有顶层 `pack.json` 和它引用的 24 张 PNG。导入后 App 使用 `user-naiwa` 安装目录；同名再次导入更新同一只宠物。

## 5. 保留的声音资源

六段原始 WAV、来源记录、提取与生成脚本，以及 `app/assets/pet_sounds/naiwa/` 的已生成资源继续保留。原笑声约 25.286531 秒，录音及重采样字节均不改变；它不决定当前动画播放时长。

音频不注册到 App、不随 APK 或宠物 ZIP 打包。`sounds.json` 的 cue 仅关联当前保留的动作作为资源参考；录音文件完整保留。详细来源与许可见 [音频说明](../../app/tool/pet_src/naiwa/audio/README.md)、[ASSETS.md](../../ASSETS.md) 与 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)。

## 6. 验证

绘图自检验证帧数、颜色、透明度、身体连通块、手臂长度、五官和嘴部锚点；构建测试验证源图与打包图逐像素一致、所有引用有效、全部动画可达和重复构建一致。

App 测试使用 main 的解析器与导入库验证包，按真实聊天页播放器覆盖四种待机小动作、工作档位、完成动作及返回、导入、三连点及六连点。声音资源单独校验，不能把资源校验通过写成 App 支持声音。
